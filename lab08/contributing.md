Branching Policy

This repository uses GitHub Flow for development. The main branch contains completed work and is protected from direct changes.

New work should be done on a separate feature branch created from main. Feature branches should have names that describe the work being done.

Branch Naming

Feature branches should use clear names that describe the purpose of the work. For example, a branch for Lab 8 could be named lab08-feature.

Branches should be created from main and should only contain changes related to the feature being developed.

Pull Requests

When work on a feature is complete, the feature branch should be pushed to GitHub and a Pull Request should be opened to merge it into main.

The Pull Request should include a short description of the changes. At least one other contributor should review and approve the Pull Request before it is merged.

Merging

Changes should only be merged into main after the Pull Request has received the required approval.

After the Pull Request is merged, the feature branch can be deleted because the completed work is now part of main.
